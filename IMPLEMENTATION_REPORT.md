10. **Production limitations:** integration candidate only. Hosted checkout necessarily includes PayFast merchant ID/key in browser form fields, conflicting with an absolute prohibition on frontend credential visibility; passphrase remains private. Outbox delivery is at least once and consumers must use idempotency. Default source checks use IPv4 socket peer addresses. COMPLETE is the supported one-time ITN status; trusted administrative terminal decisions require reconciliation of late payments. Pending exception reporting is not provider polling or settlement reconciliation. Refunds, recurring billing, subscription management, split/marketplace settlements, other gateways, disputes and analytics are not implemented. See PRODUCTION_READINESS.md.

11. **Commits:** implementation and verification commits are recorded in `git log` on the dedicated branch; their hashes are included in the delivery reply. The documentation commit contains this report. No remote push was possible because there is no remote configuration.

12. **Install elsewhere:** add a Composer path repository pointing to this directory (or a private VCS repository after publication), run `composer require vmt/payfast:dev-codex/vmt-payfast-integration`, `php artisan vendor:publish --tag=payfast-config`, and `php artisan migrate`; configure the PAYFAST variables, register a scoped idempotent listener and view gate, and schedule `payfast:dispatch-outbox`. Full instructions and server-order usage are in INSTALLATION.md and README.md.
